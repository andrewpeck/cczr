#+title: CCZR
#+options: toc:2

A fast log colorizer written in Rust, spiritually based on [[https://github.com/cornet/ccze][CCZE]].

This is AI slop but I find it very useful. It is much faster than CCZE.

Running on a Vivado log file (32 kB) I get runtimes of 2220 ms seconds for CCZE,
25 ms for CCZR. Almost 1000x speedup. For large log files ccze has noticeable slowdown.

Reads lines from stdin, applies ANSI color highlighting based on the log
format detected, and writes to stdout.  Drop it into any pipeline.

#+begin_example
journalctl -f | cczr
tail -f /var/log/syslog | cczr
cat vivado.log | cczr
#+end_example

* Installation

Download a prebuilt Linux x86_64 binary from the [[https://github.com/andrewpeck/cczr/releases/latest][latest release]]:

#+begin_src sh
tar xzf cczr-*-x86_64-unknown-linux-gnu.tar.gz
install -m755 cczr ~/.local/bin/
#+end_src

Or install directly from GitHub with cargo (no local clone needed):

#+begin_src sh
cargo install --git https://github.com/andrewpeck/cczr
#+end_src

Or clone and install locally:

#+begin_src sh
git clone https://github.com/andrewpeck/cczr
cargo install --path cczr
#+end_src

Or build without installing:

#+begin_src sh
cargo build --release
# binary at ./target/release/cczr
#+end_src

* Usage

#+begin_src
USAGE:
    cczr [OPTIONS]

OPTIONS:
    -n, --no-color        Disable ANSI color output (plain text pass-through)
        --list-plugins    List available plugins and exit
    -h, --help            Print help information
#+end_src

** Examples

#+begin_src sh
# Colorize a Vivado implementation log
cat impl_1/impl.log | cczr

# Colorize live systemd journal output
journalctl -fu myservice | cczr

# Pipe Apache access log
tail -f /var/log/apache2/access.log | cczr

# Strip color (useful for further processing)
cat app.log | cczr --no-color

# See which plugins are loaded
cczr --list-plugins
#+end_src

* Plugins

Plugins are tried in order.  /Full/ plugins consume the entire line; if none
match, /Partial/ plugins are applied in sequence to colorize sub-fields.
Lines that match no plugin fall back to word-level colorization.

| Plugin   | Type    | Log format                              |
|----------+---------+-----------------------------------------|
| syslog   | Full    | Generic syslog(8) — RFC 3164            |
| httpd    | Full    | Apache access log (CLF/vhost) and error |
| postfix  | Full    | Postfix MTA                             |
| squid    | Full    | Squid access, store, and cache logs     |
| exim     | Full    | Exim MTA main log                       |
| dpkg     | Full    | Debian dpkg/apt                         |
| php      | Full    | PHP error log                           |
| vsftpd   | Full    | vsftpd FTP server                       |
| sulog    | Full    | su(1) audit log                         |
| ulogd    | Partial | Netfilter / ulogd field coloring        |

* Color roles

Semantic color roles are mapped to ANSI styles.  A selection of the most
visible roles:

| Role      | Style       | Used for                           |
|-----------+-------------+------------------------------------|
| Date      | Cyan        | Timestamps                         |
| Host      | Bold cyan   | Hostnames and IP addresses         |
| Process   | Bold green  | Process / service names            |
| Pid       | Green       | Process IDs                        |
| User      | Bold yellow | Usernames                          |
| HttpGet   | Bold green  | HTTP GET method                    |
| HttpPost  | Bold cyan   | HTTP POST method                   |
| HttpCodes | Yellow      | 2xx / 3xx status codes             |
| Error     | Bold red    | 4xx / 5xx, error-level log entries |
| Warning   | Bold yellow | Warnings                           |
| GoodWord  | Bold green  | success, running, connected, …     |
| BadWord   | Bold red    | error, failed, denied, timeout, …  |
| Keyword   | Bold yellow | Tcl commands, highlighted keywords |
| Info      | Bold cyan   | ~INFO~ log level                   |
| Uri       | Bold cyan   | URIs / URLs                        |
| Mac       | Bold white  | MAC addresses                      |
| Version   | Bold green  | Version strings (v1.2.3)           |
| String    | Green       | Double-quoted strings              |

* Word-level fallback

Lines not matched by any plugin are scanned word-by-word for:

- Double-quoted strings → String color (matched first, so the string is colored
  as a whole rather than having paths and numbers inside it picked apart)
- IPv4 addresses → Host color
- Email addresses → Email color
- URIs (~https://…~) → Uri color
- MAC addresses → Mac color
- File sizes (~4KB~, ~1.2MB~) → Size color
- Version strings (~v3.14~, ~2.0.1~) → Version color
- Timestamps (~HH:MM:SS~) → Date color
- Hex addresses (~0x…~) → Address color
- Numbers → Numbers color
- Keywords: ~INFO~ → bold cyan; ~error~, ~failed~, ~FAIL~, … → bold red; ~running~, ~success~, ~PASS~, … → bold green

The syslog plugin also applies word-level colorization to its message body,
so keywords like ~INFO~ are highlighted even inside matched syslog lines.

* Development

#+begin_src sh
cargo test          # run all 46 tests
cargo build         # debug build
cargo build --release
#+end_src

Tests cover each plugin individually (match / no-match / color assertions)
plus the full pipeline and the word-level fallback.  Log samples are modelled
on the [[https://github.com/cornet/ccze][CCZE test corpus]].

After cloning, enable the formatting hook so commits stay ~rustfmt~-clean:

#+begin_src sh
pre-commit install
#+end_src

CI runs ~cargo fmt --check~, ~cargo clippy -D warnings~, ~cargo build~ and
~cargo test~ on every push and pull request to ~main~.

** Cutting a release

Pushing a ~v*~ tag builds a release binary and publishes it as a ~.tar.gz~
(plus a ~.sha256~) on a new GitHub Release:

#+begin_src sh
git tag v0.1.0
git push origin v0.1.0
#+end_src

Keep ~version~ in =Cargo.toml= in sync with the tag.
